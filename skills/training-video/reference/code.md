# Режим „по код“

Обучително видео за **една роля** на уеб приложение: записът влиза като потребител с тази роля и показва само екраните, до които тя стига, с курсор, осветяване и надписи в темата, синхронизиран по гласа. Механизмът: `${CLAUDE_SKILL_DIR}/screencast/`.

## 1. Профилът на продукта

Всичко за конкретния продукт живее в неговото repo, в `.training-video/`:
- `profile.md` — как се вдига демо версия, **ролите и какво вижда всяка**, етикетите на екраните, капани, какво иска собственикът. **Прочети го целия, преди да пишеш сценарий.**
- `adapter.cjs` — входът, ролите и данните за записа (вж. по-долу).
- скриптове за демо стека (напр. `stack.sh`), примери (`examples/<роля>/`: `video.json`, `script.json`, `chapters.cjs`).

**Няма профил?** Разучи repo-то: README, `docker-compose*.yml`, `package.json` (скриптове), как се влиза (dev вход, тестови потребители, seed данни), кои са ролите и екраните (вж. „Ролите — от кода“). Питай човека каквото не личи (кой да е зрителят, коя роля, кои екрани не бива да се показват). Вдигни **отделна демо инстанция** (свои портове и данни — никога dev или прод базата на някого; e2e стек на проекта е добър образец) и направи `.training-video/` по шаблона `${CLAUDE_SKILL_DIR}/screencast/adapter-template.cjs` + `profile.md`. Покажи ги на човека: те стават част от repo-то на продукта (commit — само ако човекът каже).

## Ролите — от кода, не по памет

Ролята решава какво влиза във видеото: зрителят вижда само своите екрани и бутони, а гласът не обещава нищо, което ролята не може.
- **Къде са:** проверките на правата в бекенда (декоратори/зависимости като `require_role`, `@PreAuthorize`, policies, middleware), enum/константи с ролите, менюто на фронтенда (кои точки са скрити за коя роля), маршрутите с guard, seed/фикстури с тестови потребители по роли, e2e тестове, които сменят ролята.
- **Как влиза ролята в демото:** dev вход/хедър, тестов потребител с тази роля, или назначаване през API/SQL в демо базата като подготовка извън кадър. Назначаването трябва да е идемпотентно — записът се повтаря.
- **В адаптера:** `roles` — за всяка роля `label` (както я казва приложението), `as` (с какво влиза), `home`, `screens` (до какво стига) и `denied` (до какво не бива да стига — проверява се). В `profile.md` — същото с думи и откъде в кода е взето.
- **Проверка:** `survey.cjs` (стъпка 3 от хода) влиза като ролята и отваря екраните ѝ; `denied`, който се отваря, спира с `WARN` — тогава профилът или приложението грешат и казваш на човека, преди да пишеш сценарий.

## 2. Адаптерът (`<repo>/.training-video/adapter.cjs`)

```js
module.exports = (env) => ({          // env = video.json "app" + process.env + REPO
  base: 'http://localhost:55173',     // само localhost — записът променя данни
  locale: 'bg-BG',
  check() {},                         // хвърля грешка, ако средата не е безопасна/готова (напр. dev стек вместо демо)
  async login(ctx, who, rt) {},       // who = "as" на ролята (или изрично "as"); влиза в Playwright context-а
  roles: {                            // ролите на приложението — от кода (вж. „Ролите — от кода“)
    manager: { label: 'Мениджър', as: { user: 'manager.demo@example.com', role: 'manager' },
      home: '/orders', screens: ['/orders/new', '/reports'], denied: ['/admin'] },
  },
  describe: who => '…',               // за отчета
  path: (p, rt) => p,                 // плейсхолдъри в пътищата (напр. {org} → id на демо организацията, {link} → личен линк на rt.who)
  helpers(rt, h) { return {} },       // собствени помощници за главите: подготовка на данни, QR, SQL към демо базата…
  crawlSkip: /logout|delete/i,        // по желание: връзки, които survey.cjs --crawl не отваря
});
```

## 3. Ход

1. **Демо стекът** — по `profile.md`. Провери, че dev/прод стекът на човека не се пипа.
2. **Папката на видеото** (`video.json`): `"mode": "code"`, `"product": "<абсолютен път до repo-то>"`, `"project": "<същият път — ключът на проекта>"`, `"role": "<роля от адаптера>"`, `"app": {…за адаптера}` (по желание). `"as": {…}` вместо `role` — само за човек, който не е роля от профила. Ако има пример за ролята — копирай го и го промени.
3. **Разгледай истинския UI като ролята**, преди сценария: `node ${CLAUDE_SKILL_DIR}/screencast/survey.cjs <папка> --crawl` → `survey/<роля>/`: снимка и текст на всеки екран, до който ролята стига, и `summary.md` (заглавия, бутони, полета, отказани заявки, проверката на `denied`). Прегледай снимките. Етикетите в сценария — оттам и от i18n, не по памет. Гласът не обещава нещо, което ролята не може. Друга роля за сравнение: `--role <id>`.
4. **`script.json`** (както в `scripts/lines.py`) + за всяка глава:
   - `card` — заглавна карта (по подразбиране); `"card": false` — заглавието е надпис в страницата, докато звучи първата реплика (главите в един и същ екран; `caption_top`/`caption_left` в пиксели, ако закрива нещо).
   - Първата и последната глава с една реплика са само карта (въведение, край). Всяка друга глава се записва.
   - `role` — глава като друга роля от адаптера (напр. клиентът, който получава писмото); `as` — като конкретен човек извън ролите; `part` — номер на частта (върви сам).
   - `"continues": true` (с `"card": false`) — същата глава, продължена като друга роля: записва се отделно, но без нов номер на част и без надпис на екрана.
5. **`chapters.cjs`** — модулът на видеото:
   ```js
   module.exports = (h) => ({
     async s01() {                       // подготовка, извън кадър: връща данните в началното състояние на главата
       await h.open('/orders');
       return async () => {              // записът
         await h.beat('s01_00', async () => {});            // първата реплика (картата/надписа)
         await h.beat('s01_01', async () => { await h.click(h.page.getByRole('button', { name: 'Нова поръчка' })); });
       };
     },
   });
   ```
   Общите помощници (`h`): `move`, `click`, `typeSlow`, `spot(loc)`/`spot(null)`, `spotRect`, `union`, `zoom`, `beat(id, fn)`, `selectOption`, `pressKey`, `enter(поле, текст)` (скенер/поставяне + Enter), `nextConfirm(true)` (преди клик, който отваря `confirm()`), `open(път)`, `skip(fn, бележка)`, `page`, `sleep`, `DIALOG`; плюс помощниците на адаптера.
   - **Подготовката прави главата повторяема:** всяка глава трябва да може да се запише колкото пъти трябва, независимо от другите.
   - `beat` чака края на звука на репликата + 0,9 с — синхронът идва от самия запис.
   - `skip(fn, 'около 30 секунди по-късно')` вътре в `beat` — бавно чакане (AI заявка, отчет): `fn` се записва, но `assemble.py` го изрязва, а бележката се показва 2,5 с след среза. Изрязаното не се брои във времето на репликата. Само за чакане, за което гласът не говори — никога, за да скрие какво прави приложението.
6. **Чернова без глас:** `node ${CLAUDE_SKILL_DIR}/deck/render.cjs <папка> silence` (тишина с дължината на текста), после записвай — истинският глас по-късно.
7. **Запис:** `node ${CLAUDE_SKILL_DIR}/screencast/record.cjs <папка> <глава>` → `raw/<глава>/` (видео, `timeline.json` с грешките, `error.png` при спиране). След всяка глава прегледай кадрите (`ffmpeg` кадър на всяка реплика или `sheets.py` върху `raw/<глава>/*.webm`). `errors` трябва да са само очакваните (отказ, който главата показва нарочно).
8. **Карти:** `node ${CLAUDE_SKILL_DIR}/screencast/cards.cjs <папка>` → `build/cards/<глава>.png` в темата.
9. **Монтаж:** `python3 -B ${CLAUDE_SKILL_DIR}/screencast/assemble.py <папка>` (на Windows — Python командата от `doctor.py`) → `final/<name>.mp4` (1920×1080, -16 LUFS) + `timeline.json`; после `srt.py`.
10. **Ново преозвучаване без нов запис:** копирай звука, с който е записано, в `audio-recorded/`, генерирай новия (`narrate.py`) и пусни `assemble.py` — където новата реплика е по-дълга, последният кадър се задържа.
11. Накрая спри демо стека (по профила) и провери, че нищо от dev стека на човека не е пипано.

## Капани (общи)

| Капан | Поправка |
|---|---|
| Нативен `<select>` не се отваря в headless запис | `h.selectOption(loc, стойност)` — осветява и сменя на място |
| `confirm()` забива записа | `h.nextConfirm(true)` точно преди клика |
| Камера/скенер няма в headless | `h.enter(поле, текст)` — както ръчен скенер |
| Повторен запис дава друго състояние | подготовката на главата връща данните в началото |
| Дълго чакане (AI, отчет) в кадър | `await h.skip(() => …waitFor(), 'около N секунди по-късно')` |
| Надписът на главата закрива бутон | `caption_left`/`caption_top` в главата |
| Глава спира с грешка | `raw/<глава>/error.png` и `errors`; оправи и запиши само нея |
| Локатор хваща скрит елемент (skip link, второ меню) | `getByRole(…, { name })` с точния етикет от `survey/<роля>/summary.md` |
| `--crawl` хаби екраните за еднакви страници | отваря най-много по 2 от шаблон (`/items/<n>`); каквото липсва — подай пътя изрично |
